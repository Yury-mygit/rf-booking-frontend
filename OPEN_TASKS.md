## Подтверждённые дефекты

### BOOK-001 — повторный платёж для старой незавершённой оплаты

- Статус: открыт. Приоритет: высокий.
- Код: backend `app/core/payments.py`, `DevPayProvider.init`.
- Условие: у брони есть Payment(pending), созданный до миграции
  `payments_checkout_url`, поэтому checkout_url = NULL.
- Воспроизведение: повторно вызвать pay/init для такой брони.
- Фактически: старый платёж пропускается без запроса статуса PSP;
  создаётся новый intent. Проверка метода с подставным DB/PSP подтвердила:
  0 запросов статуса старого intent, 1 создание нового.
- Риск: две действующие страницы оплаты; если PSP уже принял старую оплату,
  но webhook задержан, появляется возможность повторной оплаты.
- Ожидается: проверить старый intent; при paid ждать webhook, при created
  восстановить checkout либо безопасно закрыть старый intent перед новым.
- Задача: исправить обработку legacy-платежей и проверить сценарии
  created / paid / declined / cancelled и одновременные pay/init.

### BOOK-002 — прежний выезд ограничивает новый выбор дат

- Статус: открыт. Приоритет: средний.
- Код: frontend `src/client/views/hotels_filter.js`,
  `openStayDatesPicker` → `openDateDrawer`.
- Воспроизведение: открыть подтверждение номера с датами 29–30 октября
  2026, когда номер занят; нажать выбор других дат и попытаться выбрать
  заезд 1 ноября.
- Фактически: календарь заезда получает maxIso = 29 октября — старый
  выезд минус сутки. Выбрать более поздний заезд нельзя. Ограничение
  воспроизведено отдельным вызовом функций с подставным интерфейсом.
- Ожидается: при выборе новой пары дат прежний выезд не ограничивает заезд;
  новый выезд учитывает min_stay_nights отеля.
- Задача: убрать ограничение прежним выездом для последовательного выбора
  пары; проверить перенос периода вперёд и отмену на каждом шаге.
